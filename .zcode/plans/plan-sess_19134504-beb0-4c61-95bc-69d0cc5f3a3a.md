# GitHub Actions 自动打包 + 自动版本号 + 应用内检查更新

仓库：`mrhuangyong/zcode-app`（GitHub 公开），gh CLI 已登录。APK 产物 = **GitHub Release 附件（assets）**。

## A. 正式签名 keystore（我生成）

1. `keytool -genkeypair` 生成 `zcode-remote.keystore`（PKCS12, RSA 2048, 10000 天）+ 随机强密码，文件存仓库外 `~/projects/aieditor/keystores/`（总结中提醒备份）。
2. `gh secret set` 直接配置：`ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`。

## B. 版本号管理

新增 `version.json`（单一事实来源）；`app.config.ts` 引用。新增 `scripts/bump-version.mjs`（patch+1、versionCode+1、buildNumber+1）。

## C. 签名注入

新增 `scripts/inject-android-signing.mjs`：CI prebuild 后解码 keystore 到 `android/app/`，把 release signingConfig 改为读环境变量；变量缺失时回退 debug 签名（本地不受影响）。

## D. Workflow `.github/workflows/release.yml`

push 到 main（bump 提交带 `[skip ci]` 防循环）：
1. checkout → node 22 → `npm ci`
2. bump 版本 → 提交 `chore(release): v1.0.1 [skip ci]` push → tag `v1.0.1`
3. `npx expo prebuild -p android --no-install` → 注入签名
4. setup-java 21 + setup-android → `./gradlew assembleRelease -x lint`
5. `gh release create vX.Y.Z`，**APK 作为 Release 附件上传**（命名 `zcode-remote-vX.Y.Z.apk`）

## E. 应用内检查更新

1. `npm install expo-constants@~57.0.11`
2. 新增 `src/lib/updater.ts`：匿名查 `api.github.com/repos/mrhuangyong/zcode-app/releases/latest`，取版本 tag 与 APK 附件 `browser_download_url`；`checkForUpdate()` 对比 `Constants.expoConfig.version`
3. `App.tsx` 启动静默检查（失败无感），`DeviceListScreen` 顶部更新卡片「发现新版本 vX.Y.Z ▸ 前往下载」→ `Linking.openURL`（Release 附件直链）；可关闭
4. 遵循 theme 语义（ultramarine 交互、mono 眉题）

## F. 测试

- `updater.test.ts`：新版本/版本相同/无 APK/网络失败
- `DeviceListScreen.test.tsx`：卡片渲染、点击打开、关闭

## G. 验证

1. `npm run verify` + lint
2. 提交推送，`gh run watch` 盯首次实跑：bump 提交、tag、Release + APK 附件
3. 下载 CI 产物装模拟器，覆盖安装验证签名一致、更新卡片弹出（本地版本低于 Release 版本时）
