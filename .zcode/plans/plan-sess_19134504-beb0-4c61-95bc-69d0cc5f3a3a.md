# 应用内完成 OAuth 登录（登录授权页改为应用内 overlay）

## 问题根因（来自远控页 3.16.2 bundle 逆向分析）

新版远控页登录流程：`startOAuthWithPolling` → 主页面**持续轮询** zcode.z.ai token 接口，同时 `openExternal(authorizeUrl)` 打开授权页：
- zai provider：`https://chat.z.ai/api/oauth/authorize?...`
- bigmodel provider：`https://bigmodel.cn/login?...`

当前 `navigation.ts` 把非 zcode.z.ai 的 http(s) 全部交给系统浏览器 → 登录在系统浏览器完成，会话无法带回应用。

**可行解**：授权页放**应用内独立登录 overlay WebView**。主远控页面不被打断、轮询继续；overlay 内完成登录后 redirect 回 zcode.z.ai 回调；Cookie 经 sharedCookiesEnabled 共享，主页面轮询拿到 token 自动完成登录。

## 改动

### 1. `src/lib/navigation.ts`（分流纯函数）
- `NavigationTarget` 增加 `'auth'`
- 新增 `AUTH_HOSTS = new Set(['chat.z.ai', 'bigmodel.cn'])`（精确 host）
- https + AUTH_HOSTS → `'auth'`

### 2. 新组件 `src/components/AuthBrowserModal.tsx`
- Props：`{ visible, initialUrl, onClose }`
- 全屏 Modal：顶栏「登录 ZCode 账号」+ 关闭按钮（testID `auth-close-button`），内嵌 WebView
- WebView 分流：zcode.z.ai（登录回调）与 AUTH_HOSTS → 在 overlay 内加载；其余 http(s) → 系统浏览器；其他 blocked
- `onNavigationStateChange`：host 变为 zcode.z.ai 时显示「登录完成 ✓」并 1.5s 后自动关闭（主页面轮询接管）
- 安全配置与主 WebView 一致（JS/domStorage/sharedCookies、mixedContentMode never）

### 3. `RemoteShell.tsx`
- `shouldStartLoad`：`'auth'` → 打开登录 overlay，返回 false（不加载、不交系统）
- `onOpenWindow`：授权域 → 打开 overlay（原 system/zcode 逻辑不变）
- 持有 `authUrl` 状态渲染 `AuthBrowserModal`

### 4. 测试
- `navigation.test.ts`：授权域 → `'auth'`；子域/相似域仍 `'system'`
- 新 `AuthBrowserModal.test.tsx`：渲染、关闭、回调域自动关闭
- `RemoteShell.test.tsx`：auth URL 返回 false 且开 overlay、不调 `Linking.openURL`；onOpenWindow 同理

### 5. 文档
AGENTS.md 安全边界：主 WebView 白名单不变（zcode.z.ai）；登录授权页仅在专用 overlay 加载（chat.z.ai / bigmodel.cn），回调后自动关闭；navigation.ts 仍是唯一分流事实源。

## 验证
1. `npm run verify` + lint
2. 模拟器实测：用会话 URL 打开远控页 → 点登录 → **应用内** overlay 出现 chat.z.ai 授权页（截图/UI dump 确认未跳系统浏览器）→ 关闭按钮可用。真实账号登录最后一步由你在真机完成确认。

## 边界说明
- 未来 web 端更换 OAuth 域名需同步 `AUTH_HOSTS`
- 授权页内如再跳第三方域名仍走系统浏览器（当前 bundle 只有 zai/bigmodel 两 provider，均在白名单内）
